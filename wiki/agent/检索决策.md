# 检索决策

本页规定 Agent 在回答前如何决定检索范围、读取顺序和证据强度。它吸收长期记忆系统的优点，但保持本库的 Markdown-first 结构。

## 铁律

**所有回答的最终事实依据必须是 raw/ 原文。** Wiki 层（来源页、概念页、专题页、对比页、子索引、术语索引）的作用是**导航和索引**——帮你快速定位到 raw 原文的哪个位置有相关信息。Wiki 层本身不是回答的终点。

## 决策顺序

1. 读取 [[wiki/agent/回答协议]]，确认回答边界。
2. 读取 [[wiki/agent/问题路由]]，判断是否已有明确入口。
3. 读取 [[wiki/agent/术语索引]]，处理术语、方名、概念和版本名。
4. 按问题类型进入 `wiki/概念/`、`wiki/专题/`、`wiki/对比/` 或 `wiki/来源/`，**定位到相关的 raw 原文位置**（文件名 + 行号范围或切片）。
5. **必须回到 raw 原文核对**：读取 raw 原文中对应段落，确认 wiki 摘要没有遗漏、扭曲或添加原文没有的表述。长资料可先用 `derived/chunks/manifest.md` 定位切片。
6. 以 raw 原文为准输出回答。如果 wiki 摘要与 raw 原文不一致，以 raw 为准，并在回答中指出摘要的不足。
7. 回答前检查是否存在知识缺口；不足之处直接说明。
8. Agent 可以做适度综合，但综合部分必须标注 `[Agent 综合]`，不得写成资料原意。

## 问题类型与入口

| 问题类型 | 优先入口 | 回源要求 |
|----------|----------|----------|
| 术语定义 | `wiki/概念/` | 若要引用具体说法，回来源页或 raw |
| 学习路径 | `wiki/专题/` | 需要核对课程顺序时回来源页 |
| 方剂/药物/穴位 | `wiki/来源/` 与相关概念页 | 涉及剂量、操作、现实使用时回 raw 并加医学边界 |
| 版本差异 | `wiki/对比/` | 必要时读两个版本的来源总览 |
| 医案细节 | `wiki/来源/` | 必须回 raw 或 derived 定位后回 raw |
| 观点争议 | `wiki/专题/`、`wiki/对比/` | 标明资料范围和不足 |
| 跨领域类比 | 当前领域 Wiki + 外部/其他领域资料 | 明确标注为跨域综合或 Agent 推理 |

## 轻量关系图谱

检索时不要只看关键词，也要沿页面关系继续读取：

- 概念页的上位概念、相关概念、相关方剂、相关病机。
- 专题页的适用问题、资料依据、可综合推断、回答边界。
- 来源页的 Related Concepts、后续专题候选和 raw 回源入口。
- 对比页的适用场景和版本差异。

如果页面缺少关系线索，不要临时编造；可在回答后建议后续补充。

## 知识缺口标注

回答复杂问题时，Agent 应主动判断：

- 当前知识库是否只有单一资料族支撑。
- 是否缺少现代医学、其他中医流派或反方观点。
- 是否缺少具体条文、医案或 raw 原文核对。
- 是否把跨来源综合或跨领域类比推进得过远。

不足时使用明确表述，例如：

```text
当前知识库能支持的是...
当前知识库不足以确认的是...
以下属于 Agent 基于资料的综合/推理，不是资料原文结论...
```

## 写回规则

- 如果一次回答暴露出高频缺口，优先记录到 [[wiki/agent/覆盖报告]]。
- 如果某个概念跨资料族反复出现，按 `SCHEMA.md` 创建或更新概念页。
- 如果某个问题会被反复询问，优先沉淀为专题页。
- 不因一次检索结果就创建概念页、专题页或对比页。
