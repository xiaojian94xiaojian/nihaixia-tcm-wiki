# 回答协议

本页规定 Agent 使用本知识库回答中医问题时的默认口径。

## 默认口径

采用”资料 + 适度综合”。

**优先级铁律：Wiki 层是导航工具，raw/ 才是回答依据。** 任何涉及事实性内容的回答，必须回到 raw/ 原文核对后方可输出。Wiki 页面（来源摘要、概念、专题、对比）的作用是帮你定位 raw 原文中的对应位置，不是替代原文。

- 优先使用 raw/ 原文作为事实依据，Wiki 页面用于导航定位。
- 可以跨来源综合，但必须标明综合依据来自哪些 raw 原文的具体位置。
- 如果使用模型自身知识、一般逻辑、现代医学常识或外部知识补充，必须明确标注为“脱离知识库的推理/补充”。
- 不得把 Agent 推理伪装成倪海厦观点、资料原文结论或 raw 原文内容。
- 复杂问题应说明当前知识库能支持什么、不能确认什么。
- 回答格式应服务问题本身，不强制套用固定模板；简单问题可以自然回答，复杂问题再展开结构。

## 三类内容标注

回答时应尽量区分：

| 类型 | 含义 | 标注方式 |
|------|------|----------|
| 资料原意 | 来自 raw/ 原文的内容（经过核对） | “资料中认为...” |
| 跨来源综合 | 基于多份 raw/ 资料归纳出的结论 | “综合多份资料可归纳为...” + 标注 `[Agent 综合]` |
| 脱离知识库的推理 | Agent 使用自身知识、一般逻辑或外部常识补充 | “以下不是知识库原文结论，是 Agent 推理/补充...” |

## 回答顺序

1. 先读 [[wiki/agent/问题路由]]，判断问题类型。
2. 再读 [[wiki/agent/检索决策]]，确认检索范围和要求。
3. 用 `wiki/agent/术语索引`、`wiki/概念/`、`wiki/专题/`、`wiki/来源/` 等导航层**定位到具体 raw 原文位置**（文件名 + 行号或切片）。
4. **必须读取 raw/ 原文对应段落**，以 raw 原文为准输出回答。
5. Wiki 摘要与 raw 原文如有不一致，以 raw 为准，并在回答中注明。
6. 如果知识库资料不足，直接说明”不足以从当前知识库确认”，再决定是否给出脱离知识库的推理。

## 医学回答边界

- 所有疾病、方药、针灸、预后和治疗相关回答，都必须说明这是资料观点整理，不替代医生诊疗。
- 不给用户下诊断。
- 不把资料里的方药直接转成现实用药建议。
- 当用户描述现实症状时，优先提醒其寻求合格医生面对面诊疗。

## 回答形态

Agent 应优先保证资料边界清楚，而不是机械套格式。根据问题复杂度选择输出形态：

- 简单定义、学习顺序、资料定位类问题：可以用自然段或少量 bullet 直接回答，并简短说明依据。
- 中等复杂问题：建议使用“结论 / 资料依据 / 综合理解”的轻结构。
- 复杂辨证、癌症叙事、医案、方药、针灸操作、现实症状相关问题：应展开资料依据、综合判断、知识缺口和医学边界。
- 只有实际使用了知识库外推理时，才单独标出“脱离知识库的推理/补充”；没有使用时不必写“无”。
- 医学边界可以简短表达，但不能省略。

完整结构仅作为复杂问题的参考，不是固定输出模板：

```text
简短结论：

资料依据：

综合说明：

脱离知识库的推理/补充：

知识缺口：

边界提醒：
```

## 不足时的处理

如果问题在当前知识库中没有足够资料：

- 不要硬编。
- 明确说明缺口。
- 可以建议需要补充哪类资料。
- 如果给出一般性推理，必须标注为脱离知识库的推理。
